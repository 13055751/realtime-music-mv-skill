# 6. Musical coupling

Use the strongest available measured data.

Priority:

```text
measured onset / beat data
        ↓
measured audio features
        ↓
waveform / envelope
        ↓
estimated timing
        ↓
nominal BPM only as fallback
```

Map musical features to parameters, not entire scenes by default.

Example:

```text
kick      → scale impulse
snare     → cursor / text flash
bass      → deformation amplitude
high freq → fine jitter / particle activity
energy    → density / brightness
silence   → decay / negative space
```

Use decaying envelopes instead of one-frame spikes.

# 7. Lyrics are events, not subtitles

Lyrics can control:

- scene transitions
- commands
- state changes
- object creation/destruction
- topology changes
- typography
- process names
- labels
- errors
- measurements
- dialogue-like UI

Semantic translation should usually follow:

```text
lyric meaning
    ↓
operation / relation / state / measurement
    ↓
visual behavior
```

For a terminal style, for example:

```text
waiting
→ process enters WAIT state

searching
→ filesystem / corpus query expands

disappearance
→ lookup returns null / empty result

memory
→ persistent cache/history panel changes
```

The actual lyric text remains the user's authoritative source; do not invent replacements for it when synchronization matters.

# Word-level timeline

**Added in v2.4.0 (field evidence: 398 words, 259 snapped to onsets; the word `DC`
fired an AC→DC stage switch at exactly 46.881 s).**

Line-level cue timing is not enough for "the picture moves when the word is sung".

Build a word-level timestamp layer for every line:

```text
1. split the line into words at syllable-count ratio   → candidate boundaries
2. snap each candidate to the nearest audio onset inside a ≤600 ms window
   with a monotonic constraint (boundaries never cross)
3. no onset in window → keep the ratio value
```

Rules:

- karaoke word-lighting and stage keyword switches consume **one shared word timeline**
  — never two independently derived clocks;
- the operative rule is one sentence: **the lamp lights / the stage switches only when
  the word is sung**;
- word timestamps are data (generated by a tool from the audio), not hand-typed numbers;
- if the lookup shape differs between modules (array vs object), verify it explicitly —
  a silent shape mismatch once disabled every word-triggered switch while all defaults
  "worked".

## Opposing concepts must take distinct forms

**Added in v2.4.0 (field evidence: user caught "DC/AC 那边图形为什么是一样的").**

When lyrics contain opposing or paired concepts (AC/DC, AD/BC, F/M, from/to …), each pole
gets its **own** graphic form — a shared drawing with a renamed label is **not staged**:

```text
AC → alternating square-wave lane
DC → constant straight lane
AD/BC → era-countdown ruler
F/M → register flip
```

The switch instant binds to the **word-level timestamp of the pole's own word**, not to
the line start. This generalizes § 7: semantic meaning must be visible as form.

## Lyric time and musical grid are separate sources

**Added in v2.4.0 (field evidence: mapping LRC to a fixed BPM grid drifted lyrics by
~0.11 s on average).**

- lyric timing comes from the measured LRC / cue file;
- beat/onset/MIDI timing comes from measured audio features;
- never resample one onto the grid of the other — a film whose lyric timestamps were
  snapped to a nominal BPM looks rhythmically tidy and sings late;
- § 1.3 (semantic time ≠ musical time) and the § 6 fallback ladder still hold.
