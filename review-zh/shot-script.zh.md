## 0. 剧本是文件——多轮写入（硬规则）

导演的产出是**落盘的剧本文件**，不是一次性回答。原因：
- 长剧本需要**很多轮写入**——单次模型输出有上下文上限，写一批、保存、继续下一批；
- 读剧几乎免费——engineer 读整份文件不会耗尽上下文，所以**不要把演出压缩进一次回答**；
- 精细化演出需要*非常多*文字——一次绝对不够。

写入协议：第一轮写骨架（镜头表行 + 每镜一句情绪）；之后每轮逐镜展开演出细节（画面上有什么、怎么动、光、节奏、观众感受）——**追加到文件，不重写已好的部分**；最后一轮通读一遍、修矛盾、检查情绪弧可读。

规则：**追加不压缩**（每轮让文件变长，最终剧本是完整累积不是摘要）；镜头表仍是骨架（与代码逐行对应的契约），但演出列写**完整散文级细节**不做缩写；上下文快满就在干净边界停下保存——**文件是工作记忆，对话只是前端**；engineer 读整份文件，大小不是问题。

# 分镜方法（Shot Script）中文审阅版

> 旧版只规定表格列，从不教怎么填。本文件补上缺失的一半：景别、舞台、情绪弧上屏、镜头语言、转场选择。

## 1.5 每镜双层交付：演出散文 + 技术拆解（硬下限）

每个镜头行在脚本正文中展开为**两块**。一行的脚本不是脚本：

- **PROSE（观众体验）**：按顺序写观众看到什么——构图、图层、焦点、运动、光、节奏、此刻感受的情绪，像剧本的场景描写，不是标签。至少几句完整句子，最好一段。
- **TECH BREAKDOWN（工程师怎么实现）**：本镜的实现方向，具体到工程师不用发明就能写码：数据源（音频 FFT bins/歌词 token/数据轴）、技术（canvas 路径/粒子系统/镜头变换/波形绘制/分词器拆分）、关键参数（bin 数、粒子数、缓动曲线名、颜色值、时长 ms）、以及什么必须确定性。**这不是代码**，是导演的实现规格。

规则：**没有技术拆解就没有镜头**（工程师要即兴发明技术的镜头=导演没执导；不确定就写清楚要达到什么效果，让工程师在 E-3 提出，但绝不空白）；**散文优先、技术其次**（观众体验决定，技术服务它）；FFT/分词器/粒子/镜头移动**只在技术拆解明确点名时才允许**，否则工程师不得自行添加（禁止发明奇观）；参考体量：3 分钟歌约 60 镜 → 脚本文件几千字，脚本只有几百字=太短，继续多轮写到每镜都有 prose+tech 两块。

## 1.6 可视设计稿——显示而非描述（硬要求）

批次获批前用户必须**看到**设计，纯文字审批禁止（"我想的和他想的完全不一样"）。

每批至少 1-3 张**静态关键帧设计稿**：HTML/CSS/SVG/canvas 静态帧（或所选运行时单时间戳渲染），表达构图/配色/排版/深度/氛围；每张对应表格里一个 shot id；设计稿是**设计草案**不是最终渲染——快、便宜、可弃；确定性：同 id + 同 t 渲染同像素。

规则：没有设计稿就没有审批（S-C 是可视门，纯文字批次直接驳回）；设计稿引领、散文解释（草图展示画面，散文论证选择，二者冲突时用户眼里的设计稿赢）；用户说"我想的不一样"→ 答案是**新设计稿**，不是更长的文字解释——迭代到画面匹配为止；保持便宜：每批 1-3 张，绝不整片渲染循环。

## 1.55 参数硬清单 + 完整示例镜头

一个镜头只有具备下列**具体数值**才算可执行。"太短"不是行数问题，而是导演给定了多少数值：

```text
1. 颜色用具体值   #RRGGBB / rgba()，每个可见表面都要有；
2. 几何用数字     x / y / w / h / radius，或具名布局规则；
3. 运动用数字     时长 ms、缓动曲线名、起点/终点值；
4. 文字用值       内容、字体族、字号 px、字重、字距；
5. 图层显式       z-index / 绘制顺序 / 混合模式；
6. 数据映射点名    哪个音频/数据信号驱动哪个参数；
7. 节奏用 ms      镜头何时开始、关键动作何时命中；
8. 确定性注明      什么被播种 / 什么必须可复现。
```

技术拆解答满 8 项 → 工程师只做翻译；只答 3-4 项 → 工程师发明其余部分——那不是执导，是把设计交给运气。不确定就给数字，不要给感觉。

**完整示例镜头（密度下限，file 里每个镜头都应达到此密度）**：

```text
SHOT 012 | t=74.2s-78.6s | lyric: dancing in the dark | scale: CLOSE-UP

PROSE: 单词 dark 以深蓝夜光字形大尺寸悬于屏上，彼此轻微错相，每个字形随慢正弦呼吸。其后低频 FFT 带膨胀为柔和蓝色雾霭充满下半屏。一道暖色高光（dancing 强调）如手电光般扫过字形。情绪：亲密、深夜、克制。

TECH BREAKDOWN:
  - canvas，确定性；audio = FFT via AnalyserNode, 128 bins, t = audio.currentTime；
  - 字形：分词器拆出的 12 个字形，Space Grotesk 96px 字重500，色 #0A1E3C 带辉光(shadowBlur 24, #2E5CFF)；
  - 单字形相位 = hash(glyphId)*0.7s，y呼吸 = 4px*sin(2*PI*(t-phase)/2.8s)；
  - 雾：低频均值(bins 0-15)映射径向渐变 alpha 0.15-0.45，色 #1B2A52；
  - 高光：柔和径向(r 160px) rgba(255,214,170,0.55)，x = easeInOut(t-74.2)/4.4s*900，y=300，时长4.4s，曲线 cubic-bezier(0.65,0,0.35,1)；
  - 确定性：seed=74.2，所有随机 hash(sceneId, shotId, glyphIdx)；
  - 图层：字形 z=3，雾 z=1，高光 z=2，雾用 screen 混合。
```

## 1. 表格格式

```text
| # | timecode | shot name | stage content | camera / motion | transition | emotion intent |
```

每行与代码镜头表一一对应（同 id 同 timecode），情绪弧必须能单独从表读出。代码与脚本不一致 = 两者之一错了，渲染前修。

## 2. 景别选择（什么时候用什么）

```text
特写     单个词/字形/眼睛   → 亲密、执念、精准
近景     主体填满画面      → 情绪、在场、坦白
中景     主体+部分上下文   → 动作、对话、能动性
全景     主体在世界中很小  → 孤立、尺度、敬畏
大远景   世界主导          → 上下文、命运、转场标记
```

景别变化是标点：突然推近落情绪拍，突然拉远重置舞台。每个拍定一个景别并坚持，不要无理由游走。

## 3. 每镜编排（用导演语言回答）

画面有什么？焦点在哪？怎么动？（staging §4 运动家族）何时变？（词时间戳/拍/情绪拐点）观众为什么感受到？（明确写情绪意图）。三层舞台逐镜适用。没焦点的镜=占位符不是镜。

## 4. 情绪弧上屏（弧线必须可见于镜头与运动选择）

```text
calm  → 慢推、宽构图、低能量、长镜
build → 不对称、密度上升、取景收紧
burst → 快切、运动模糊/拉伸、全屏接管、高对比
tail  → 衰减、负空间、长静态、安静微动
```

脚本说"calm"但镜头"每秒一切"= 脚本在撒谎。情绪列与镜头列必须一致。

## 5. 镜头语言（code-rendered 也适用）

PAN 平移/推进/拉出/TILT 垂直扫/HANDHELD 有界抖动（必须确定性）/STATIC 静止。镜头跟着音乐重音走，不跟它对着干。落在拍上的推近=冲击，偏 200ms=漂移。

## 6. 转场选择（语义标点，不是默认胶水）

硬切=新命令/新段/能量尖峰；淡入淡出=连续/记忆/梦；滑动=推进/过程/流；重绘=重载/重初始化；reflow=布局变化/成长；morph=变形/身份转变；corruption=错误/不稳定/崩溃；terminal clear=重置/静默/重生；process takeover=舞台换主（歌词/传输条保持存活）；黑场=死亡/静默/终。一个 cue 一个转场=失败模式；不传达任何信息的转场=装饰。

## 7. 重复纪律

重复歌词是"角色"不是"重播"：首次出现建立母题语言；第二次说已建立的语言（同语法、更密/进化）；绝不复制粘贴相同场景。对立概念（AC/DC、AD/BC、F/M）必须各自成形——换标签不算编排，切换绑在词自己的时间戳上。

## 8. 退场纪律（开启必关闭）

每个开启的状态有确定性关闭；歌词画板在句尾切断绝不拖进淡出尾；母题第二次复用已建立的语言。高潮时锁住永不关闭的参数会把结尾重绘成另一部电影。
